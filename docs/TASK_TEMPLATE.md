# AI 작업 요청 템플릿

## 작업 ID와 목적
예: DF-001, 일정이 많을 때 빠르게 찾기

## 사용자 동작
어느 화면에서 어떤 조작을 하면 어떤 결과가 나오는지 작성

## 완료 조건
관찰 가능한 동작, 오류/빈 상태, 필요한 테스트를 작성

## 제약
지원 OS, 기존 데이터 호환성, 수정하지 않을 범위를 작성

## 수행 요청
AGENTS.md를 읽고 관련 코드를 조사한 뒤 구현한다. scripts/verify.sh와 필요한 화면 검증을 수행한다. 변경 내용, 검증 결과, 미검증 항목을 보고하고 BACKLOG 상태를 갱신한다.

## PR 완료 절차

자동 테스트·iOS 빌드·화면 QA·실기기 검증을 모두 통과한 뒤 PR을 작성한다. 검증을 위한 브랜치 push는 먼저 진행할 수 있다. 미검증 항목이 있으면 초안 PR도 새로 만들지 않는다. 기존 초안은 검증 완료 전 일반 PR로 전환하지 않는다. 실패를 성공으로 표현하지 않으며, 병합과 배포는 별도 지시 없이 수행하지 않는다.

TASK마다 독립 브랜치와 PR 하나를 작성한다. 여러 TASK를 동시에 개발해도 PR을 합치지 않는다. PR 제목에 해당 TASK ID 하나를 표시한다.


## PR 생성 전 필수 검증 기록

- 자동 테스트·빌드: 명령, 코드 커밋, 실제 결과
- 화면 QA: TASK별 사용자 시나리오와 결과, 실행 환경
- 실기기: iPhone 모델, iOS 버전, 설치한 코드 커밋, 실제 동작과 증거
- 실패·미검증·진행 중 항목: 해결 전 PR 생성 금지
